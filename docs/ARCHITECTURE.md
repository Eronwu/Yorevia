# Yorevia V0.1 架构与实现决策

## ADR-001：独立架构与运行时选择

不 Fork 相册服务。生命周期记录和人物关系属于 Yorevia 的领域模型，照片索引、检测与解码由现成库完成。

讨论阶段的 React、D3、FFmpeg、ExifTool 是候选，不是本版已经接入的依赖。**当前实际代码**选择 Tauri 2 + 无框架 TypeScript/CSS/SVG + Python/OpenCV/Pillow + SQLite。原因是首版减少构建与运行时依赖，同时可在没有 npm 网络访问的环境验证前端。图谱使用轻量 SVG 布局，展示最多 24 人；不宣称已经实现 D3 的大图布局。后续需要复杂状态管理时，可替换前端，不改变 RPC 和资料库格式。

```text
TypeScript UI（时间轴 / 人物 / 故事 / 隐私）
   │ 精确的 method + params，明确的错误与任务状态
   ├── 桌面：Tauri Rust → 私有 stdin/stdout → Python sidecar
   └── 开发预览：127.0.0.1 HTTP + 随机令牌 + Origin/Host 校验
                                          │
                             Service / 可取消任务队列
                               ├── Vault / SQLite
                               ├── Media / 原件只读与缩略图
                               └── FaceEngine / YuNet + SFace
```

应用运行不需要厂商服务器。桌面路径只通过系统目录选择器授权；前端没有任意执行 shell、读取任意本地文件或网络访问的通用能力。原片访问必须由登记的 asset ID 解析。开发预览不是桌面安全边界的等价验证。

## ADR-002：数据不是一棵目录树

`Asset ↔ Face ↔ Person` 表达照片中观察到的人像。`Relationship(a,b,label,start,end)` 保存人工记录的真实关系。`Story ↔ Asset / Person` 让一个没有照片的故事也可以存在。

| 对象 | 稳定身份与含义 |
|---|---|
| Asset | 完整文件 SHA-256；同内容不同路径视为同一资料，修改内容产生新资料 |
| Location | 来源 ID + 相对路径；多个位置可指向同一 Asset |
| Face | 照片内的人像框、特征、头像、Person ID、人工修正状态 |
| Person | 独立 UUID，不以姓名或某一张脸作为主键 |
| Relationship | 人工声明，允许带日期，不能由同框次数自动生成 |
| Story | 独立 UUID，正文、时间和引用；无媒体引用也合法 |

重新扫描移动后的文件可按完整内容哈希重连；不承诺视觉近似、转码、修图、重新压缩后还能自动认作同一文件。快速增量扫描利用大小和修改时间，用户可强制完整校验。

## ADR-003：本地资料库与持久化

```text
用户选择的位置/
└── YoreviaVault/
    ├── vault.json          格式、版本和资料库 ID
    ├── vault.sqlite        权威数据源，事务写入
    ├── .lock               防止同机重复进程打开
    ├── thumbs/             媒体缩略图缓存
    ├── faces/              人像裁切缓存
    ├── records/            预留目录；不是当前自动 Markdown 存储
    └── exports/            显式生成的 ZIP 快照
```

V0.1 **没有**同时写 Markdown 和 SQLite 两份主数据，也没有实时云同步。JSON / Markdown 在导出时生成。说明这一点比宣称“数据库随时可从原片重建”更重要：人名、人工关系和故事不在原片中，必须备份资料库。

WAL + 外键 + 独立连接事务；源目录离线、遍历不完整或取消扫描不能把未见文件标记为删除。更新后的数据库版本高于本程序时拒绝打开。尚无跨设备合并、迁移回滚或自动恢复向导。

## ADR-004：人像分析不等于身份确认

YuNet 找到人脸，SFace 提取特征，归一化后与人物特征均值比较。初版用保守阈值和第一/第二候选差距减少误合并。同一照片的两个检测结果不自动归到同一人物。

这不是经过本项目数据集标定的识别置信度。不同年龄、侧脸、遮挡、旧扫描件、双胞胎等都可能分错。每次输入单张照片是一个事务；失败回滚人物/人像记录与本次裁切。人工合并保留被合并称呼与说明，拆分保留已确认的现有分组。整理任务运行期间暂不允许合并/拆分，避免旧中心向量覆盖人工决策。

目前是增量近邻归类，不是全局 DBSCAN/HDBSCAN；导入顺序可能影响初始分组。手动合并/拆分是纠错机制，不是模型准确率承诺。尚无一键撤销历史。

## ADR-005：日期必须有证据

照片 EXIF DateTimeOriginal > 完整文件名日期推测 > 未知。文件系统修改时间只用于增量扫描，不参与人生排序。用户修正优先保留，不被重新扫描覆盖。当前人工日期为完整日历日期，不支持“约 1990 年代”等模糊范围。

视频本版只尝试首帧缩略图和文件名日期；未解析视频容器拍摄时间，未做视频内人物识别。GPS 只读取和保存在本地，不请求在线地理编码或地图服务。

## ADR-006：打包和更新

Python sidecar 由 PyInstaller 在目标 OS/CPU 上生成；不跨平台伪造二进制。Tauri release 配置显式嵌入 sidecar。开发配置直接使用项目 `.venv`，避免要求开发者预先有发行二进制。

本版没有自动更新服务。CI 验证安装包构建后仅上传短期 artifacts；带标签构建才创建草稿 prerelease，仍需人工验收、签名/公证和依赖许可审计后才能对外发布。
